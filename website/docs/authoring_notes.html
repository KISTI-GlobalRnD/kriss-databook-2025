작성 가이드 / Authoring Notes

이 문서는 본 프로젝트의 배포판(final report) 문서를 작성할 때의 규칙과 권장 형식을 정리한 “작성법 노트”이다. 목표는 (1) 외부 독자가 이해할 수 있는 논문형(서술형) 기술 문서를 일관된 톤으로 작성하고, (2) 향후 Quarto 기반 출력(웹/북)과 다른 포맷(예: HWP/Docx) 변환에서도 의미가 유지되도록 하는 데 있다.

적용 범위
  • 본 가이드는 final_report_site/docs/*.qmd에 새로 작성/확장되는 모든 문서에 적용한다.
  • 로컬 파일 경로, 내부 변수명, 실행 로그 같은 “개발/운영 디테일”은 원칙적으로 본문에서 배제하고, 필요한 경우에만 부록/재현성 섹션에 한정하여 기술한다.

1. 배포판 문서 원칙 / Principles

(1) 독자 관점 우선
“우리 팀이 무엇을 했는가”가 아니라 “독자가 어떤 근거로 이해·재현·검증할 수 있는가”를 중심으로 쓴다. 절차/파라미터/의사결정은 ’왜 그렇게 했는지’가 설명되어야 한다.

(2) 내부 구현 노출 최소화
다음 항목은 외부 배포판 본문에서 가능한 한 피한다.

  • 로컬 폴더 구조(예: Output/..., Data/...)와 내부 파일명
  • 코드 함수/클래스명, 내부 변수명(예: cluster_micro, ppm_series_val)
  • 운영 로그/캐시 경로/배치 스크립트 등 실행 편의 정보

필요한 경우에는 “재현성 / Reproducibility” 섹션을 별도로 두고 일반화된 설명(예: “중간 산출물 테이블”, “정규화 매핑 사전”)로 표현한다.

(3) 용어 일관성
프로젝트 핵심 용어는 동일 표현을 반복 사용한다(동의어 남발 금지). 예:

  • 표준과학 연구 영역 / 표준과학 연구 분야
  • 표준과학 연구 영역 핵심 문헌 집합(14만건)
  • 표준과학 연구 영역 확장 문헌 집합(111만건)
  • 표준과학 연구 영역 최종 문헌 집합(109만건)
  • 연구주제 클러스터(거시/중시/미시)

(4) 근거 기반 서술
결론형 문장에는 (i) 인용문헌, (ii) 정량 결과, (iii) 분석 설계(가정/제약) 중 최소 하나를 연결한다.

2. 권장 문서 구조(논문형) / Paper-Style Structure

챕터(또는 보고 단락)는 아래 흐름을 권장한다.

  1. 배경/문제정의: 왜 이 분석이 필요한가(정책·기관·학술 맥락), 기존 접근의 한계
  2. 데이터 범위/정의: 문헌 집합, 기간, 포함/제외 기준, 표본/결측 처리
  3. 방법론(설계): 모델/알고리즘/정규화/평가 기준, 파라미터 선택 논리
  4. 구현(절차): 재현 가능한 수준의 절차 설명(단, 내부 코드명은 배제)
  5. 산출물/지표 정의: 표/수식/정의(‘빈도’ vs ‘문서 커버리지’ 등)
  6. 검증/품질관리: 민감도, 안정성, 예외 처리, 오류 가능성
  7. 해석과 한계: 결과를 어떻게 읽어야 하는지, 한계/향후 과제
  8. 참고문헌: 본문 인용과 연결되는 문헌 목록

3. Quarto(qmd) 작성 규칙 / Quarto Rules

3.1 헤딩 레벨 / Heading Levels

  • # : 문서 제목(페이지 제목)
  • ## : 큰 섹션(2~6개 권장)
  • ### : 세부 섹션(과도하게 쪼개지 않도록 주의)

북 프로필에서는 자동 번호가 붙으므로, 헤딩 텍스트에 수동 번호(“1-2-3)” 등)를 중복해서 넣지 않는 것을 권장한다.

3.2 자산(그림/데이터) 경로 / Assets

  • 이미지/도표는 docs/assets/ 하위에 둔다.
  • docs/*.qmd에서 참조할 때는 assets/... 상대 경로를 사용한다.

3.3 교차참조(그림/표) / Cross-References

Quarto 교차참조를 사용하면 웹/북 출력에서 번호와 링크가 자동으로 관리된다.

권장 라벨 규칙 - 그림: #fig-... (예: #fig-1-2-2-hybrid-relatedness) - 표: #tbl-... (예: #tbl-1-2-2-parameters) - 라벨은 영문 소문자/숫자/하이픈만 사용한다(공백/특수문자 금지). - 번호가 필요한 그림/표는 반드시 라벨을 부여한다. 라벨이 없으면 캡션은 출력되더라도 번호·교차참조가 관리되지 않는다.

그림 예시

![표준과학 연구지형도 개요](assets/landscape_overview.png){#fig-landscape-overview}

…그림 @fig-landscape-overview는 표준과학 연구 분야의 전체 구조를 요약한다.

표 예시

| 항목 | 설명 |
|---|---|
| 핵심 문헌 집합 | … |
| 확장 문헌 집합 | … |

: 문헌 집합 정의 {#tbl-corpus-definition}

4. 캡션·도표·수식·인용 처리 / Captions, Tables, Equations, Citations

4.1 그림 캡션 / Figure Captions

  • 그림 캡션은 이미지 마크다운의 대괄호 텍스트(![캡션](...))를 사용한다.
  • “그림 1.” 같은 번호는 직접 쓰지 말고, 라벨({#fig-...}) + 교차참조(예: @fig-...)로 처리한다.
  • Notion 등에서 가져온 원고는 ![image.png](...) 같은 “파일명 캡션”이 남는 경우가 많으므로, 반드시 의미 있는 캡션 문장으로 교체한다.

캡션 문장 작성 팁 - 캡션은 “그림이 보여주는 핵심”을 짧은 명사구로 작성한다(너무 긴 문장 지양). - 분석 설계나 파라미터를 캡션에 모두 넣기보다, 캡션은 요약하고 세부는 본문에서 설명한다. - 동일한 유형의 그림은 캡션 표현을 반복 사용해 일관성을 유지한다(예: “연도별 추세”, “네트워크 구조”, “클러스터 분포” 등).

(고급) 다중 패널/그룹 그림 여러 이미지를 한 그림 번호로 묶어야 할 때는 figure div와 fig-subcap을 사용한다.

::: {#fig-example-panels layout-ncol=2 fig-cap="(패널) 비교 결과" fig-subcap="true"}
![](assets/panel_a.png)
![](assets/panel_b.png)
:::

4.2 표 캡션 / Table Captions

  • 표 캡션은 표 아래에 : 캡션 {#tbl-...} 형태로 작성한다.
  • 표 제목(캡션)에는 표 번호를 직접 쓰지 않는다(번호는 렌더링에서 자동 부여).

4.3 수식 / Equations

  • 수식은 가능한 한 정의(변수, 분모/분자, 단위) 를 함께 서술한다.
  • 수식이 본문 해석에 중요하면, 문장으로 한 번 더 풀어서 설명한다.

4.4 인용 / Citations

배포판에서는 두 가지 방식 중 하나를 택해 일관되게 운영한다.

  1. 수기 인용(권장: HWP 변환 대비)
    본문에 Kim & Lee (2025) 또는 (Kim, 2025; Lee & Kim, 2026)처럼 직접 표기하고, 문서 말미에 참고문헌 목록을 둔다.

  2. 서지 파일 기반(Quarto citeproc)
    references.bib 같은 서지 파일을 두고 Quarto 인용 문법([@kim2025])을 사용한다. 웹/북에서 참고문헌 자동 생성이 필요할 때 유리하나, 최종 HWP 편집 흐름과 충돌할 수 있으므로 팀 합의가 필요하다.
